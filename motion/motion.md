## 2. 이징과 기본 규칙

### 2-1. 이징 (속도 곡선)

> 이징은 움직이는 동안 속도가 어떻게 바뀌는지 정하는 곡선입니다. 이름은 `scene.md`와 같습니다.

| 이징 이름 | cubic-bezier 값 | 속도 변화 |
| :--- | :--- | :--- |
| ease-out | `0, 0, 0.2, 1` | 처음 속도가 가장 빠르고, 끝에서 속도 0 |
| ease-in | `0.4, 0, 1, 1` | 처음 속도 0, 끝에서 속도가 가장 빠름 |
| ease-in-out | `0.4, 0, 0.2, 1` | 처음과 끝 모두 속도 0, 가운데가 가장 빠름 |
| linear | `0, 0, 1, 1` | 처음부터 끝까지 같은 속도 |
| back-out | `0.34, 1.56, 0.64, 1` | 끝 값을 약 10% 넘었다가 끝 값으로 돌아옴 |
| 컷 | — | 0프레임 만에 바뀜 (길이 0) |

### 2-2. 기본 규칙

- 카메라는 고정합니다. 휴대폰 화면 전체가 움직이는 것은 S1 0 ~ 0.92 등장 한 번뿐입니다.
- **장면마다 다른 등장** (2026-11-11 사용자 요청): S1 옆에서 들어와 통통 튀기 / S2 검색창을 기준으로 한 번에 커지기 / S5 로고 둘레 별 반짝이며 등장. S3(팝업 커짐)·S4(그라데이션 원)는 그대로입니다.
- 화면 전체 색은 1초에 3번 넘게 바뀌지 않게 합니다 (깜빡임 접근성 기준).
- 글자를 읽어야 하는 화면은 움직임이 끝난 뒤 0.9초 이상 멈춥니다 (`scene.md` 각 장면의 "멈춤").
- 쓰지 않는 움직임: 화면 전체 색 컷 전환, 확대해서 뚫고 지나가기, 옆으로 밀기, 사선 조각 덮기 (`reference.md` 3장 "제외", R1 2.4 ~ 2.5초, 3.0 ~ 3.4초, 5.4 ~ 5.6초, 6.6 ~ 7.0초)
  - 예외: S1 휴대폰 등장만 옆(오른쪽 화면 밖)에서 들어옵니다. 사용자 요청이며, 화면을 통째로 밀어내는 전환이 아니라 첫 등장 한 번이라 `reference.md`의 제외 이유("같은 화면에서 이어진다는 느낌이 끊김")에 해당하지 않습니다.

## 6. 소리 큐 표

> 시각은 3 ~ 5장의 동작 시작 시각과 같습니다. R1의 음악은 쓰지 않습니다 (`reference.md` 머리말).
> **배경음악 없이 효과음만** 씁니다. 타자 장면에는 키보드 소리, 장면이 넘어갈 때는 올라가는 맑은 음을 넣었습니다.
> 출퇴근길에 소리를 끄고 보는 경우가 많아서, 소리가 없어도 자막과 화면만으로 내용이 전달되게 만듭니다.

### 6-1. 소리 파일

- **모든 소리는 ffmpeg로 수식(사인파·잡음)을 계산해 직접 만든 것**입니다. 녹음이나 외부 음원을 쓰지 않아 저작권 문제가 없고, 출처 표기도 필요 없습니다.
- 위치: `motion/sound/`
  - `sound_30s.wav` (무손실), `sound_30s.m4a` (AAC 192kbps): 아래 큐를 모두 합친 30초 트랙. 영상 편집 프로그램에 0초부터 그대로 넣으면 됩니다.
  - `sfx/`: 효과음 낱개 파일 20개 (48kHz 스테레오 wav). 시각을 따로 조정할 때 씁니다.
  - `make_sfx.sh`: 효과음 20개를 만드는 스크립트. 소리 높이·길이를 바꿀 때 고칩니다.
  - `mix.sh`: 효과음을 큐 표대로 합쳐 `sound_30s.wav`·`.m4a`를 만드는 스크립트. 맨 위 `CUES` 목록(시각, 파일, 음량)을 고치면 큐가 바뀝니다.
  - 다시 만들기 (Git Bash에서): `cd motion/sound` → `bash make_sfx.sh` → `bash mix.sh` (ffmpeg 필요)
